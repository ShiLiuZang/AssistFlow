# V0 初始规划（历史记录）

日期：2026-09-22。阶段：可点击视觉原型，等待页面方向反馈。

本文件承接 Minihelp 的成品化架构、函数契约和链路规划。本轮“后台页面”指客服及管理员操作界面；真正的后端服务仍按既有架构文档分阶段建设。

## 1. 本轮效果

打开同目录 `index.html`，顶部可切换三个产品视角，左侧可切换业务页面。

| 页面 | 核心任务 | 本轮交互 |
| --- | --- | --- |
| 客户咨询页 | 提问并得到处理结果 | 发消息、查演示订单、看知识引用、转人工、确认退货申请、查看服务记录 |
| 客服工作台 | 理解上下文并接待客户 | 搜索和筛选会话、接管、回复、内部备注、预设辅助草稿、查订单、建工单、结束接待 |
| 知识库 | 把可核对的内容发布给助手 | 搜索、筛选、添加文本草稿、编辑、提交审核、发布、预设回答测试 |
| 工单中心 | 跟进售后直到解决 | 搜索、筛选、新建、查看详情、领取、填写处理结果、标记解决 |

三个视角使用同一份内存数据。客户咨询页对应工作台的“林女士”；其他会话用于展示队列密度与切换。顶部的角色切换是设计评审工具，正式产品按登录身份和权限显示入口。

## 3. 布局与信息优先级

### 客户端

桌面版：店铺服务入口 + 右侧聊天窗口。移动版：以聊天为主，快捷动作贴近输入区。

客户应始终知道：谁在接待、当前是否等待、申请是否只是提交、下一步由谁处理。商品订单在用户需要时展开，避免挤占聊天。

### 客服工作台

固定导航 → 会话队列 → 当前聊天 → 客户与订单侧栏。接管与发送放在聊天区，工单创建连接会话上下文。内部备注与对客回复必须显式区分。

宽屏显示三栏；较窄窗口折叠客户侧栏，可从聊天标题栏打开资料。移动端以客户咨询为主要使用场景，客服工作台提供应急查看，复杂运营操作以桌面为主。

### 管理后台

工作台沿用同一导航和控件语言。知识页先看发布状态，工单页先看待处理项；统计数字只为当前任务提供上下文。报表另设页面，避免把大量指标塞进接待界面。

## 4. 优先确认的三个流程

### 人工服务

客户转人工 → 排队 → 客服原子认领 → AI 停止自动发送 → 客服回复 → 客户收到 → 结束接待。

原型可演示视角间消息变化。正式实现必须补：认领冲突、在途 AI 消息取消、消息发送/失败状态、断线恢复和重复发送保护。

### 售后跟进

核对订单 → 提出申请 → 客户确认 → 生成工单 → 客服领取 → 记录进展 → 填写结果 → 客户查看。

原型保留“申请不是退款成功”的语义。正式实现必须由业务服务验证资格、权限、幂等和状态迁移，浏览器不得直接改资金状态。

### 知识发布

整理内容 → 保存草稿 → 核对范围 → 提交审核 → 构建并验证索引 → 激活发布版本 → 测试引用。

原型只演示草稿、审核、发布状态。正式版需要解析失败、索引失败、发布中、回滚等中间态；只有可用索引成功激活后才显示“已发布”。

## 5. 页面与后端职责

沿用已写入 `Minihelp/docs/PRODUCT_CONTRACTS.md` 的服务边界，以下均为计划接入。

| UI 区域 | 后端服务职责 | 前端须处理的结果 |
| --- | --- | --- |
| 会话队列与接管 | conversations 查询、原子认领、分配、模式切换 | 新消息、认领成功、版本冲突、无权限 |
| 聊天与草稿 | messaging 可靠收发；turns 编排；草稿与发送分离 | queued / sending / sent / failed、流中断、重试 |
| 客户与订单上下文 | identity / orders / products 授权查询 | 空结果、多个订单需选择、外部服务不可用 |
| 申请确认与工单 | actions 确认；tickets 创建、分配、状态迁移 | 待确认、过期、重复提交、处理冲突、结果回告 |
| 知识库 | knowledge 草稿、校验、审核、版本激活；jobs 异步构建 | 上传/解析/索引进度、失败重试、发布/停用/回滚 |
| 配置和系统管理 | 成员权限、渠道状态、受控配置、审计和健康检查 | 校验失败、凭证到期、敏感项遮盖、操作记录 |

UI 只负责收集输入、展示状态与发出明确的用户意图；权限、订单归属、金额和状态变更由服务端决定。正式接口与事件 schema 应在开始接入之前明确，避免 UI 字段直接绑定图节点内部状态。

## 6. 正式页面必须补齐的公共状态

- 初次加载、空数据、搜索无结果、请求失败与重试。
- 未登录、会话过期、无权限、对象不存在。
- 网络离线、正在重连、消息发送失败、可安全重发。
- 表单校验、未保存离开提醒、操作进行中、重复点击保护。
- 会话被他人接管、工单版本冲突、确认动作过期。
- 文件上传进度、类型/大小限制、预览和删除。
- 键盘操作、可见焦点、屏幕阅读器名称、减少动态效果。

## 7. 建议实施顺序

1. **确认 V0**：确定导航、主要布局、配色、客服模式切换语义与缺失的关键页面。
2. **补页面稿**：优先登录、成员权限、配置引导；补主页面的失败、空态、冲突态。
3. **前端基础**：确定路由与组件方案；抽离消息、订单、工单、知识状态组件；建立 mock API 和 schema。
4. **后端最小链路**：身份权限 → 可靠消息 → 接管/回复 → 工单确认和跟进。先让一条真实 Web 会话完整走通。
5. **知识与运营**：接入异步构建、版本发布、测试；再补商品、渠道、报表、系统运维页面。
6. **成品验收**：真实模型、数据库、渠道和浏览器验证；再验证并发、重连、回滚、备份恢复和权限边界。

## 8. 演示边界

- 不连接 API、模型、数据库、支付或外部渠道。示例政策、姓名、订单、工单都是演示内容。
- 数据只保存在本页内存，刷新会重置；不支持多浏览器实时同步。
- 三种配色共享布局，可通过右上角色切换旁的色点切换：森绿（默认）、纯白、暖纸。
- 图片位置明确写“商品图待补”。现有像素猫图标直接复用 Minihelp 的原始 SVG。
- 所有新文件位于独立原型目录，未修改 Minihelp 运行代码。
