## 5. 需要单独补建的能力

- 真实人工认领、分配、接待模式互斥、在途 AI 发送取消、人工消息可靠发送。
- 工单列表、负责人、状态迁移、结果回告与权限；原有创建工单接口不等于完整工单系统。
- 正式身份认证、成员和店铺授权、后台作业权限、审计与受控配置。
- 知识的文档版本、审核权限、索引激活和回滚；原 pending/done 向量化状态不等于发布版本状态。
- 真实商品、订单、物流和售后适配；演示订单不能作为业务验收。

## 6. 迁移顺序及退出条件

1. **本轮原型评审**：确认导航是否好找、原有功能是否都有位置、日常客服与高级后台是否分工清晰。交付后停在此节点。
2. **固定迁移清单**：按上表逐项关联现有前端事件、接口、返回字段、异常状态和数据来源。
3. **迁移公共外壳**：统一导航、表格、表单、加载与错误组件，保留原 URL，先迁移只读总览。
4. **逐模块接入**：知识录入与审核 → RAG/观测/主题 → 模型/作业 → 客户流式聊天；每个模块完成后核对旧功能，不一次性替换全部页面。
5. **实施新增业务链路**：接待、工单、权限与真实渠道按产品架构文档推进。
6. **真实验收后切换入口**：旧数据可见、错误可恢复、原操作不丢失、权限和幂等有效；原路径至少提供兼容跳转和回退方式。

## 7. 本轮检查口径

进行 JavaScript 语法、资源加载、导航渲染与必要的页面查看。后台运行全部是内存模拟，不调用模型，不运行训练、清库或真实评估。没有把原型检查计为原项目或生产服务验收。
